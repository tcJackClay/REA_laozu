# 宝可梦 · 行囊探险：融合规格 v1

日期：2026-10-23。分支：`poke`。起点：`d8e6c29`。本阶段为可玩的最小闭环，不代表完整内容移植。

## 已确认产品规则

- 保留当前竖屏的顶部信息、场景、属性条、下方背包/事件、底部六导航及下钻返回骨架。
- 全部美术主题换为宝可梦；**不自行绘制图形，使用 PokeCatch 已有图像**。CSS只负责布局、面板、边框和文字，canvas只合成原图、裁边、平移和绘制战斗文字。
- 全部现有页面使用 PokeCatch 的黑色主题。源字体、精灵球底纹、卡片纹理、像素按钮和属性色通过build-poke-theme.py提取，不沿用修仙版米色/绿色/仿古金按钮。[主题验收](DARK-THEME.md)。
- 每局抽取一只新的宝可梦；单宝可梦作战。招式卡块与携带道具均占背包格位。
- 已装包招式按冷却自动释放，道具实际产生被动/消耗效果；没有装包的奖励不能在战斗中生效。
- 遭遇没有直接捕捉分支。击败宝可梦获得独立抽取点，用于后续抽取，不消耗精灵球库存。
- 毕业伙伴进入收藏；收藏未来用于道馆/对战塔和有限探险支援。核心探险仍每局抽新伙伴。
- 本阶段只实现抽取、两场战斗、奖励整理、结算收藏及再次抽取。道馆实战、支援、进化、培育及在线服务不在完成范围。

## v1 可调整的融合经济

以下为本轮实现默认值，不是 PokeCatch 或原修仙游戏的原始规则，也不是已完成平衡验收的正式数值。

|项目|默认行为|
|---|---|
|首次开局|免费抽取一次|
|后续抽取|3抽取点；妙蛙种子、小火龙、杰尼龟各1/3|
|单次击败|立即+2抽取点、击败数+1、本局等级+2；进入奖励阶段即保存|
|路线|常青小径，两场固定遭遇：绿毛虫、小拉达|
|初始伙伴|Lv.5，生命90，初始一个本系招式卡块|
|第一批奖励|对应物种进阶招式卡块+橙橙果|
|第二批奖励|学习装置|
|毕业|保留伙伴等级和唯一身份，背包不带入下一局；重复物种保留独立个体|
|战败|救援结算、保留已获得抽取点；本局伙伴可收入收藏并标记救援归来|
|救援补给|没有进行中探险、首次免费已使用、余额不足3时，补足至3；充足时不可重复领|

后续经济讨论需特别关注重复收藏容量、补给长期经济和招式解锁。当前奖励按物种固定给出，**没有执行原 PokeCatch 的学习等级门槛**。

## 背包规则

7列×6行，左上原点，x向右、y向下。初始招式2×1，进阶招式2×2；橙橙果1×1，学习装置2×1。支持鼠标拖拽、触屏选择后点格、旋转、已装物品移出到当前待整理列表。

放置前检查边界与碰撞；非法拖放不改变原位置。战斗中不允许改包。至少一个已携带招式才能开战。待领取道具显示在上方场景，全部入包后点击下方中央的“前进”，直接进入下一战或结算；没有返回事件按钮。

待整理列表是当前奖励事务的表现，不是独立可永久囤积的暂存池。本阶段没有重铸、合成、开格、商店及工具图鉴；不挂无效工具按钮。

## 战斗规则

源数据：PokeCatch 有效 POKEDEX、MOVES、TYPE_CHART。区分物攻/特攻及对应防御；本系1.5和原属性克制表参与伤害。v1公式：

```text
floor(((2 × 本局等级 / 5 + 2) × 原招式威力 × 原种族攻击 / 原种族防御 / 50 + 2)
      × 本系倍率 × 属性克制倍率 × 携带增幅)
```

这是融合公式，不是原完整战斗：无命中/暴击/性格/闪光/天气/原选招系统；原种族值不是原等级公式计算后的最终面板。

- 初始招式冷却1.8秒，进阶招式2.6秒，首次施法在600ms。
- 第一敌人34生命、每2.2秒5伤害；第二敌人65生命、每2.2秒8伤害，首次攻击1800ms。
- 橙橙果：生命不高于55%且尚存活时恢复25，每场一次。本轮为自动触发的携带效果，不消耗收藏道具。
- 学习装置：所有招式伤害×1.2，同类不叠加；此作用是融合适配，非原作经验分配效果。
- 同一时间先结算己方招式，再结算仍存活敌人的攻击。生命归零立即停止战斗。
- 离开探险页面或隐藏浏览器时暂停战斗，不做离线补算。返回恢复同一战斗，刷新也不重新生成奖励。

## 状态与事务

```text
无run → draw → ready → battle → reward → event
                                  ↑          ↓
                                  └─第二战───┘
event（第二战完成）→ settlement → 收藏写入 → 无run → 再抽取
battle（失败）→ settlement（救援）
```

存档键 `poke-fusion-v1`，与 `laozu-web-v9` 和原 PokeCatch 的 `gachamon-save-v1` 隔离。不迁移旧修仙存档。刷新统一回据点，进行中run保留。

抽取先验证余额、扣点、生成唯一run再保存；击败只从battle进入reward时发点；结算记录run ID并写入唯一个体后清空run。返回/预览不扣点。动画不是再次结算的触发器。
