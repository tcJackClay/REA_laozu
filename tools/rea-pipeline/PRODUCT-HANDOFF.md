## 2. 产品定位与已经确定的工作原则

- 核心玩法是游历培养弟子；主线是关卡挑战副玩法，不能反过来以主线替代游历。
- 主要交付为浏览器可玩的竖屏版本；手机上的图形大小、位置、间距、遮挡和点击区域是重点。
- 当前优先级是山门可视内容完整，再依次核对六项导航及下钻窗口；暂不继续扩展深层战斗公式。
- 数值可以近似，但入口、状态、消耗、奖励、返回和继续必须构成闭环。近似必须写入审计，不能包装成原版公式。
- 资源和逻辑应主动检索原 APK、热更新资源及源码，不应只按用户截图做静态页面。
- 隐藏节点需要核对解锁、平台、活动和父节点条件；不能为了“资源齐全”而全部常驻显示。
- 不复制参考账号姓名、余额、运营倒计时、在线聊天或活动资格，不编造服务器结果。
- 每轮更新总清单，截图验证后提交并推送。开发存档没有长期兼容承诺；修改时仍须说明影响。

## 3. 产品信息架构与主要用户链

底部统一六项：**弟子 / 祈愿 / 山门 / 主线 / 玩法 / 仙盟**。刷新统一回山门，正在进行的游历保留，并通过山门“游历中”重新进入。

### 3.1 山门与管理

山门承载玩家头像、姓名、老祖等级、战力、资源栏、建筑、任务、侧栏活动、快捷入口和导航。建筑包括功法、长老、游历、古宝、坊市、福地、灵宠等；是否显示由原条件和当前本地进度决定。

头像操作链：山门头像 → 个人信息（UIOtherInfo）→ 更换头像 → 头像/头像框/称号/气泡四标签 → 预览 → 使用 → 返回。预览不落账，使用才保存。展示弟子最多三位，确认保存、取消丢弃草稿，和战斗布阵分别维护。

### 3.2 游历核心闭环

山门游历 → 黑底招生入口及抽取动画 → 入学档案、随机姓名/天赋及配点 → 主修/辅修功法 → 随行长老 → 游历场景 → 事件/战斗 → 奖励整理 → 四项工具 → 返回事件 → 继续 → 毕业/失败结算与弟子归档。

事件包括剧情、选择、战力条件、商店、神通、灵宠、法宝奖励、战斗、炼丹、挖宝、转轮和渡劫等。网页事件候选、掉落与战斗数值仍有离线适配。不是所有配置记录都经过自然流程逐条操作。

奖励整理和事件日志是不同状态；返回仅关闭整理视图，不能重新生成或重复领取当前批次。领取多批次后回事件，继续才推进下一节点。工具返回应恢复调用上下文。

四项工具：重铸消耗法宝实例并累计进度/生成新法宝；开格确认消耗并检查位置；图鉴可下钻详情再返回；储物袋显示当前游历弟子的功法、长老、属性、共鸣和法宝。内部奖励队列不能被解释为原版独立“暂存池”玩法。返回箭头按状态出现，不能常驻所有界面。

### 3.3 弟子和副玩法

弟子列表 → 筛选/排序 → 详情 → 换装、重生、魂石、特殊幻化；宗门防守布阵有独立草稿和确认。特殊外观通过公共入口用于详情、布阵和游历战斗。

祈愿用于获取及收藏；主线有章节、关卡、布阵和战斗；玩法页包含本地挑战。仙盟和跨服/渠道/在线系统尚不能作为已完成产品能力交接。

### 6.1 状态、存档与事务

主存档键为 `localStorage['laozu-web-v9']`，状态含 version、disciples、inventory、run、资源及各版本扩展字段。域名和端口会影响存档隔离；5173和5180不是同一份存档。

展示弟子绑定稳定 rosterId/UUID，不能使用数组索引代替身份。个人外观拥有/到期另存 ownedPlayerAppearances；离线拥有记录不表示原服务器授权。
