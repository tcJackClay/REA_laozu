# 第十一版：录取标签与功法选择

## 原始依据

使用 APK 提取的资源及已安装版本热更新 2610131532。REA 对更新后的 Assembly-CSharp 做静态成员检查，ILSpy 读取同一程序集的方法体；未运行或注入游戏进程。
程序集 SHA-256：`c0c9533b719ae312542d6e9fda26f0f7627fb828c474681a20986bba7ccfb2b8`。

- `UIDiscipleBirth.ConfirmOpen` 发送 BUILD_DISCIPLE 请求；姓名、弟子能力由服务端创建结果提供。`BaseDiscipleData.GetName` 直接返回 Name。客户端不包含完整的服务器抽取算法。
- `InnateAbilityItem.SetAbility` 以掩码 22 选择类型 1/2/4，按类型排序；`InnateAbilityElement.OnBtn_Click` 用 `cfg_Ability.szDesc` 显示锚定词条的提示。
- `UIDiscipleBirth.OnBtn_RandomClicked` 仅分配属性点；录取前检查剩余点数，之后打开 UISelectSeedling。
- `SelectSeedlingWidget.OnSelectSeeding`：先主修，再辅修；两槽已满时替换最近选择对应槽；再次点击已选项取消；空主修时不自动晋升辅修。
- `SeedlingComparer`：品质降序、星级降序、元素升序、ID 降序。原客户端只展示已解锁且元素功能开放的功法。
- `UISelectSeedling.UpdateProp` / `SeedlingData.UpdateDiscipleEnhance`：星级索引取 arrSecondAttribute 的 star+1，辅修倍率取 Misc 3100。当前配置值 10000，即 1.0，修正原网页固定减半。
- `UpdateSkill` 只取主修怒气技能；技能按 arrAngerSkill 的星级阈值从 BattleSkill 读取。
- UISelectSeedling 提取 186 个节点、127 个精灵，使用原 RectTransform 转换器；五列列表使用原 180 格宽、横间距16、纵间距75、顶部及左侧30。

## 本次实现

- 姓名不再固定为截图中的曹灵悦；新弟子从原 RandomName 表组合姓名。
- 标签保存为原 Ability 配置 ID，按类型排序；六槽显示、品质底色、点击说明与刷新保持。
- 功法页原背景、标题、信息区域、双槽、效果区域、列表、筛选、返回和选择长老；长按查看实际配置说明。
- 选择、取消、替换、筛选保持、未选主修拦截、返回录取、刷新回山门后恢复；功法选定后使用原表星级加成和辅修系数接入现有培养流程。
- 功法星级来自可选 `state.seedStars`，解锁列表来自可选 `state.seedUnlockedIds`。

## 明确边界

服务器抽取概率、互斥与数量规则尚未采集。本地随机预览采用一个性格、一个体质和三个不重复天赋，从原表均匀选择，属于可替换的演示生成器，不能称为原版抽卡算法。旧弟子无 traitIds 时保留先前参考样本，避免刷新重新抽取。原模型外观仍为已恢复的女弟子，尚未根据抽取结果随机换装。

未导入账号解锁信息时，列表展示原配置完整目录、默认零星；这不是原版账号所有权。弟子基础数值和加点仍沿用本地样本，尚未恢复全部百分比修正与账号加成。真实战力缺失时显示“—”，不继续使用原型战力公式冒充原版。图鉴目前是名称目录，完整图鉴与长老页仍需后续对齐。
